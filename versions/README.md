# 版ごとのアプリ（Claude Code が仕様書から作ったもの）

講座の回ごとの到達点のアプリを、**講師の仕様書（`仕様書_回ごとの版`）を Claude Code に渡して実際に作らせた**ものです。
完成形（この `example_app/` 本体）とは別に、回ごとの姿を動かして見せるために置いています。データはすべて架空（霧沢精機の不適合報告書110件）。

| フォルダ | 回 | 中身 | 動かし方 | ポート（この PC） |
|---|---|---|---|---|
| `v1.1_第2回/` | 第2回 | 一覧・詳細・絞り込み・backend（FastAPI＋SQLite）。pytest 36件・Playwright 16件 | Docker なし（uv と npm） | API 8110・画面 5210 |
| `v2.1_第3回/` | 第3回 | 第2回の版に、Docker Compose と簡易的な AI アシスタント（OpenCode＋MCP の読み取りの道具、ローカル LLM） | Docker Compose | API 8120・画面 5220・OpenCode 4120 |

仕様書の 8000・5173 は、この PC では別のアプリが使っているので読み替えています（各フォルダの `CLAUDE.md`）。

## 各フォルダの中身

- `app/`・`docs/`・`data/`・`CLAUDE.md`・`README.md`：Claude Code が作ったそのまま（git の main の最後の状態）。起動の手順は各フォルダの `README.md`。
- `記録/`
  - `作る様子_再生.mp4`：Claude Code が作っていく様子。ヘッドレス（`claude -p`、stream-json）で動かした実際の記録から、Claude Code の画面に似せて再生したもの（待ち時間は詰めて早送り。上の帯に実時間）。
  - `アプリの操作.mp4`：できあがったアプリを Playwright で操作して録画したもの（字幕つき）。
  - `依頼文/`：送った依頼（① 計画 → ② 承認して作る → ③ 確かめる）。
  - `会話の記録.md`：Claude の説明と、道具の呼び出しの一覧（パスなどは伏せた）。
  - `git の履歴.txt`：開始時点からのコミット。

## 作り方（2026-10-13）

1. 作業フォルダ（`~/ai_seminar_2026/lesson02`）に、仕様書 v1.1・模擬データ・`CLAUDE.md` だけを置いて「開始時点」をコミット。
2. Claude Code（Opus 5.5）に、計画モードで計画 → 講師が読んで答える → 自動モードで作る → 受け入れ条件を確かめる、の3つの依頼を送る。
3. 第3回は、第2回の結果をコピーして（`lesson03`）仕様書を v2.1 に差し替え、`CLAUDE.md` に Docker と LLM の決まりを足して同じ流れ。
4. 動画は `tmp/series6/versions/`（`replay.py`・`record_app.py`）、書き出しは `export_version.py`。

## 作る途中で Claude Code が見つけたこと（第2回）

- 講師の仕様書 v1.1 の食い違い：AC-v11-06・07（マスタに既定の語彙を足す）が 01〜04（データの値から作る79件）と合わない／`critical` の表示が 05 は「緊急」、00・03 は「重大」／「不良数が多い順」に使う並べ替えのキーが API に無い。→ 推奨案で直してから作った（`v1.1_第2回/docs/変更点.md`）。
- 画面の不具合（開始日と終了日を続けて入れると開始日が消える）を e2e テストで見つけて直した。

## 作る途中で Claude Code が見つけたこと（第3回）

- 範囲：講師の仕様書 v2.1 は道具15本（書き込み・画面の操作・Ontology を含む）と AI パネルまで。第3回は「簡易的な AI アシスタント」に絞り、作らない要件と AC に「第3回では作らない（後の回）」を先に書いてから作った（読み取りの道具5本・`/chat`・Docker Compose）。
- 実際の LLM（gemma4:26b）での確認は15問。直す前は2問が不合格：
  - 「表面キズは何件？」：マスタの使用件数（`usage_count`）を件数として答え、報告書を数える道具を呼ばなかった。
  - 「KZ25-0043 を画面で開いて」：報告書番号のリンクを付けなかった。
  - AI への指示（system・AGENTS.md・MCP の instructions）を直して、15問とも合格した（各問1回の合格なので、いつも同じとは限らない）。
- 「GENOS M560-V の不良は何件？」に、1文字違いの GENOS M660-V の件数で答えた → 指示に例を書き足して直した。
- 402（OpenRouter の残高切れ）は確かめられないので、Ollama の URL を存在しないパスにして同じ失敗の経路（`info.error`）を確かめた。
- gemma4:26b は、KZ25-0043 の対策の文の一部を崩すことがある（「解禁する」→「解ceptする」など。道具の値は正しい）。
- 録画のときに見えたこと：同じ会話で同じ質問をもう一度すると、道具を呼ばずに前の回答から答えることがあった（「そのターンで道具から取った値だけで答える」が守られない例）。「KZ25-9999」には、道具の返した JSON をそのまま答えることがあった。
