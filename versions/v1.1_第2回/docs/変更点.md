## v1.1 の修正（2026-10-13、土台を作る前に直したもの）

仕様書どうしの食い違いと、決まっていなかったことを直した。新しい機能は足していない。

| # | 何を直したか | 理由 | 直した文書 |
|---|---|---|---|
| 1 | AC-v11-06 のマスタの項目数を、データの値だけから作る数（customer 10・process 8・machine 10・operator 29・phenomenon 12・factor 10、計79）にした。AC-v11-07 の機械の選択肢を10件にし、「a61nx を選ぶと3件」で確かめるようにした | 01・02・03・04 はデータの値だけから作る（79件）と書き、07 だけが例アプリの既定の語彙（process 14・machine 12・factor 20）を前提にしていた。既定の語彙の中身はどこにも定義されていない | 07 |
| 2 | 重大度 `critical` の画面表示を「緊急」から「重大」にした | 用語表（03 §3.4）と帳票（00）は「重大」。03 §3 で、画面の選択肢は用語表の言葉を使うと決めている | 05 |
| 3 | 一覧 API の `sort` に `defect_count` を足し、並び順「不良数が多い順」を `-defect_count` にした | 例アプリでは「不良数が多い順」が新しい順と同じになる既知の問題があった | 02・04・05 |
| 4 | 並べ替えの決まりを書き足した：`severity` は重さの順、同じ値は `defect_id` で同じ向き、知らない名前は `-` の向きを残して `occurrence_date` | 決まっていなかった（重大度を文字列で並べると意味のない順になる） | 04 |
| 5 | 逆向きの期間の 422 の形を書いた（`type` は `date_range`、`loc` は `["query", "date_from"]`） | 「FastAPI 標準の形」とだけあり、要素の中身が決まっていなかった | 04 |
| 6 | 一覧の URL クエリに `page`・`per_page` を足した | 同じ URL を開けば同じ一覧（同じページ）になるようにするため | 05 |
