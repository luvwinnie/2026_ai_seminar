# 試験・運用仕様書

> 仕様書 v1.1（第2回の終わり(確かめて直した版)）。前の版から変わったところは `変更点.md`。

本書は、DefectReport AI の受け入れ条件（AC）と、その確かめ方を定める。
要件の番号（FR・NFR）は `01_要件定義書.md` のもの。
期待値は、模擬データ `data/defect_reports.csv`（110件、発生日 2025-04-07〜2026-03-15）から数えた値である。

---

## 1. 確かめ方の決まり

- 1つの受け入れ条件は「操作」「期待値」「確かめ方」を組で書く。
- 番号は `AC-v10-01` のように、その条件が入った版と連番で付ける。後の版でも番号は変えない。
- 後の版で期待値が変わる条件（道具の本数など）は、同じ番号のまま、その版の値を書く。
- 前の版の条件は、後の版でも満たす。
- 期待値は、元データ `data/defect_reports.csv` から pandas で数えて書く。計画や資料の数字は写さず、必ず検算する。
- API で値を確かめてから、画面で同じ値が出ることを確かめる。
- 「0件」と「失敗」は別の結果として扱う。0件は条件に合う報告書が無いこと、失敗は値を取れなかったことである。
- 確かめた結果は、日付・コマンド（または操作）・件数や値を組で残す。
- 基準の URL は、API が `http://localhost:8000`、画面が `http://localhost:5173`。ポートを変えたときは読み替える。
- 「例アプリには未実装」は、講座で作るアプリに求めるが、完成形の例アプリにはまだ入っていない条件を示す。例アプリの今の振る舞いを添える。

---

### 2.2 v1.1：日付の検査・失敗の表示・マスタ

| 番号 | 操作 | 期待値 | 確かめ方 |
|---|---|---|---|
| AC-v11-01 | `GET /api/reports?date_from=2025-13-01` | 422。`detail` に、どの引数がなぜ不正かを書く。画面は日本語の理由を出す | status と `detail`。例アプリには未実装：今は不正な日付を無視して、200・110件を返す |
| AC-v11-02 | `GET /api/reports?date_from=2025-10-01&date_to=2025-09-01` | 422 と理由（date_from が date_to より後） | 同上。例アプリには未実装：今は 200・0件を返し、0件と区別できない |
| AC-v11-03 | 期間の両端 | `date_from=2025-09-08&date_to=2025-09-21` は7件（9/08 の KZ25-0042 と、9/21 の KZ25-0047・0048 を含む）。`date_from=2025-09-17&date_to=2025-09-17` は2件（KZ25-0045・0046） | 両端を含まないと5件・0件になる。発生日は date 型で比べる |
| AC-v11-04 | 一覧の読み込みに失敗させる（一覧を開いたまま backend を止め、条件を変える） | 表と件数を消し、失敗の原因と「再試行」を出す。「条件に一致する報告書がありません」は出さない | 画面を見る。例アプリには未実装：原因は赤い帯で出すが、表と件数は前の値（初めての読み込みなら0件の表示）が残り、「再試行」は無い |
| AC-v11-05 | `GET /api/masters` | 6種（customer・process・machine・operator・phenomenon・factor）を返す。各項目の `usage_count` の合計は、どの種類も110。`usage_count` が1以上の項目の数はデータの異なり数と同じ：customer 10・process 8・machine 10・operator 29・phenomenon 12・factor 10 | pandas の `nunique()` と比べる |
| AC-v11-06 | 同上（初めての取込の直後） | マスタはデータの値だけから作る。項目の数は customer 10・process 8・machine 10・operator 29・phenomenon 12・factor 10（計79）で、`usage_count` が0の項目は無い。`GET /api/masters/unknown` は404（定義していないパス） | `usage_count` が0の項目を数える。例アプリには既定の語彙も入れる違いがある（process 14・machine 12・factor 20） |
| AC-v11-07 | 画面 `/reports` の機械の選択肢 | マスタの machine と同じ10件。a61nx を選ぶと3件 | 選択肢を数える |

検算のコード（リポジトリの直下で実行）：

```python
import pandas as pd
df = pd.read_csv("data/defect_reports.csv")
d = df["occurrence_date"]                                   # 'YYYY-MM-DD' の文字列
len(df)                                                     # 110
(df.machine_name == "a61nx").sum()                          # 3
d.between("2025-09-01", "2025-09-30").sum()                 # 7（両端を含む）
df[(df.machine_name == "a61nx") & d.between("2025-09-01", "2025-09-30")].defect_id.tolist()  # ['KZ25-0043']
((df.machine_name == "a61nx") & d.between("2025-10-01", "2025-10-31")).sum()                  # 0
df[["customer", "process", "machine_name", "operator_name", "phenomenon", "factor"]].nunique()
# customer 10, process 8, machine_name 10, operator_name 29, phenomenon 12, factor 10
```
