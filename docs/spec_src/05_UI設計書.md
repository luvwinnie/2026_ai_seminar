# DefectReport AI — UI設計書

本書は画面の構成・レイアウト・遷移・配色・部品の決まりを定める。API の入出力は `04_API設計書.md`、項目の定義は `03_データモデル設計書.md`、要件の番号（FR-・NFR-）は `01_要件定義書.md` に従う。
AI アシスタントの中身（道具・プロンプト・ガードレール）は `06_AI設計書.md` に書く。 <!-- v2.0 -->

## 1. 前提と技術

- React 19 + TypeScript（Vite）、MUI、React Router。1つの画面に1つのルートを割り当てる
- グラフは Recharts（折れ線・棒・パレート図・円・p 管理図）。ページはルートごとに遅延読み込みし、Recharts を使うページを最初の読み込みから外す <!-- v4.0 -->
- チャットの本文は react-markdown と remark-gfm で表示する（表・箇条書き・太字） <!-- v2.0 -->
- 画面の文字はすべて日本語（NFR-10）。重大度・状態・4M はコード値で受け取り、画面で日本語に直す

| 項目 | コード値 → 画面の表示 |
|---|---|
| 重大度（severity） | critical＝緊急、high＝高、medium＝中、low＝低 |
| 状態（status） | open＝未対応、in_progress＝対応中、completed＝完了 |
| 4M（category_4m） | Man＝人、Machine＝機械、Material＝材料、Method＝方法。空は「未分類」 |

- API は相対パス（`/api/…`・`/health`）で呼ぶ。開発では Vite のプロキシが backend（ポート 8000）へ渡す
- Docker Compose では frontend（nginx）が `/api` と `/health` を backend へ渡す <!-- v5.0 -->
- 絞り込みの状態は URL クエリ（useSearchParams）に持つ。再読込やリンクの共有で同じ条件が開く <!-- v1.0..v1.1 -->
- **状態の正本は URL クエリ**。人の操作も AI の画面操作（`ui_navigate`）も同じ URL クエリを書き、画面は URL を見てデータを取り直す。AI が開いた条件を、人がそのまま直して使える <!-- v2.0 -->
- 例外はテーマ（ライト／ダーク）と AI パネルの開閉で、ブラウザ（localStorage）に持つ <!-- v2.0 -->
- 入力中の値などは各画面の中に持ち、画面をまたぐ値（テーマ・AI パネル）だけを上位に持つ（過度な抽象化をしない。NFR-08） <!-- v2.0 -->
- 入力中の値などは各画面の中に持つ（過度な抽象化をしない。NFR-08） <!-- v1.0..v1.1 -->

### 2.4 AI パネル

- 全ページに置く常駐のパネル。中身は `/chat` と同じ部品（ChatPanel）で、会話は同じ DB に保存される
- 閉じても、画面を移っても、パネルを消さない（アンマウントしない）。AI が回答の途中で画面を動かしても、会話と逐次表示が切れない
- `/chat` を開いているときはパネルを隠す（同じ会話を二重に出さない）
- 開閉はメニューの「アシスタント」と、パネル見出しの「≪（パネルをたたむ）」。開閉の状態はブラウザに残す（`chatPanelOpen`）。初めて開くときは幅 1200px 以上なら開き、それ未満なら閉じる
- 幅は 400px <!-- v2.0..v4.1 -->
- 幅は既定 400px。右端をドラッグして 300〜640px に変えられ、ダブルクリックで 400px に戻る。幅はブラウザに残す（`chatPanelWidth`）。ドラッグは 1200px 以上のときだけ <!-- v5.0 -->
- 見出しは「AIアシスタント」と、新しいチャット・履歴（会話の一覧をメニューで出す）・たたむの3つのボタン

- 表の列：報告書ID・発生日・部品名・現象・機械・重要度（色つきのチップ）・ステータス（色つきのチップ）・不良率（小数2桁の %）。不良率は API の `defect_rate` をそのまま出す
- キーワードは入力が止まって 300ms たってから URL に書く。ほかの絞り込みは選んだときに書く。条件が変わったら1ページ目に戻す
- 並び順：新しい順（既定、`-occurrence_date`）・古い順・損失額が大きい順・不良数が多い順
- ページ送り：1ページ 10・25・50 件（既定25）
- 絞り込みはすべて AND（例：機械 a61nx かつ 期間 2025-09-01〜2025-09-30 → KZ25-0043 の1件だけ。期間を 2025-10-01〜2025-10-31 にすると0件の表示）

- 絞り込みの項目は、ステータス・重要度・機械・工程・客先・担当者・現象・4M・並び順と期間（AI の `ui_navigate` で渡せる条件と同じ） <!-- v2.0 -->
- 状態・重要度・4M の選択肢は固定の語彙。機械・工程・客先・担当者・現象の選択肢は `GET /api/masters` から作る（用語表と同じ値。画面に候補を書かない） <!-- v2.0..v4.1 -->
- 状態・重要度・4M の選択肢は固定の語彙。機械・工程・客先・担当者・現象の選択肢は `GET /api/masters` から作る。無効にしたマスタの値は「（無効）」を付けて残す（過去の報告書を探せるように） <!-- v5.0 -->

URL クエリ：

| キー | 意味 | 例 |
|---|---|---|
| `q` | キーワード | `q=補機` |
| `status`・`severity` | 状態・重大度（コード値） | `status=open` |
| `machine`・`process` | 機械・工程（マスタの表記） | `machine=a61nx` |
| `customer`・`operator`・`phenomenon` | 客先・担当者・現象 | `phenomenon=表面キズ` | <!-- v2.0 -->
| `category_4m` | 4M | `category_4m=Man` |
| `date_from`・`date_to` | 期間（YYYY-MM-DD、両端を含む） | `date_from=2025-09-01&date_to=2025-09-30` |
| `sort` | 並び順 | `sort=-total_cost` |
| `mode` | `smart` のときスマート検索 | `mode=smart&q=治具の固定が甘くてワークがずれた` | <!-- v3.0 -->

<!-- v3.0 -->
スマート検索（`mode=smart`）：

- 「キーワード｜スマート検索」の切り替えで入る。`q` は両方で同じものを使い、`mode=smart` のときだけ URL に `mode` を付ける
- 自然文を入れて Enter か「検索」を押したときだけ検索する（打つたびには検索しない）。`GET /api/reports/search` を上位15件で呼ぶ
- 結果の列：報告書ID・部品名・機械・工程・現象・内容（抜粋）・類似度（小数3桁）。並べ替えとページ送りは出さない

### S9 時系列（`/analysis/trends`）

月ごとの推移と、工程が統計的な管理状態にあるかを見る（FR-DB-02・06）。

### S11 週次レポート（`/digests`）

### S13 関連マップ（`/analysis/graph`）

### S14 業務Ontology（`/analysis/ontology`）

- 実データを調べる：対象の種類（機械名・工程名・顧客名）と名前を入れ、「名前を確認」で実データの ID に解決してから、発生日の期間・「未クローズCAPAがある報告」で照会する。結果は件数・不適合率・損失などの指標と、根拠の報告書。候補を勝手に選ばない（候補が複数なら人が選ぶ）
- 「機械名は報告に記録された名称です。設備個体や工場を識別するものではありません。」と出す
- 定義と計算方法：対象・関係・指標の式と単位・制約を `quality.json` から出す

### S15 マスタ管理（`/settings/masters`）

- 無効にした値は、新しい入力の候補から外す（一覧の絞り込みには「（無効）」付きで残す）

## 7. 配色とテーマ

テーマは「CNCコックピット」：艶消しのグラファイトの面に、アンバー1色を差す計器盤。実装は `theme.ts`（`createAppTheme(mode)`）が正で、色は MUI の palette（`app`・`sidebar`・`chart`）に集め、各部品は `useTheme()` で読む。色を部品に直書きしない。

- 純黒を避け、面は base → paper → elevated の順に等しい明度差で重ねる
- 彩度の高い色はアクセントのアンバー1色だけ
- カードは影ではなく1px の罫線（hairline）で区切る
- KPI の数字と道具の名前は等幅の字（`MONO_FONT`）で出す <!-- v4.0 -->
- 重大度・状態は色だけに頼らず、ラベル付きのチップにする
- 角の丸み `shape.borderRadius` は 10

## 8. 部品の決まり

- 部品は MUI。枠は `Box`・`Stack`、メニューは `Drawer` と `List`（`components/Layout.tsx`）、一覧は `Table`、入力は `TextField`・`Select`、バッジは `Chip`
- 画面の見出しは `PageHeader`（題・補足・右側のボタン）
- 狭い画面では `PageHeader` の題とボタンを縦に積む <!-- v5.0 -->
- 状態の表示は `StateViews`（`Loading`・`EmptyState`・`ErrorState`）の3つだけを使う（§5）
- 重大度・状態のチップは `SeverityChip`・`StatusChip`（`components/Chips.tsx`）
- 報告書の入力フォームは `ReportForm` 1つを、取込の確認と手動入力で使う <!-- v3.0..v4.1 -->
- 報告書の入力フォームは `ReportForm` 1つを、新規作成（取込の確認・手動入力）と編集で使う <!-- v5.0 -->
- 期間フィルタ `PeriodFilter`：全期間・直近3・6・12ヶ月のプリセットと開始日・終了日。値の正本は URL クエリ（`date_from`・`date_to`、時系列では `months` も）。一覧・サマリー・分析の各画面で同じ部品を使う <!-- v4.0 -->
- 期間フィルタのプリセット「直近Nヶ月」の基準日はデータの最新の発生日にする（今日にすると、模擬データでは直近の期間が0件になる） <!-- v4.1 -->
- 例アプリのプリセットは今日の日付から数える。データの最新の発生日（2026-03-15）から数える直しは未実装 <!-- v5.0 -->
- KPI の表示は `KpiCard`（等幅の数字・左端のアクセントの線）、グラフの枠は `ChartCard` <!-- v4.0 -->
- チャットは `ChatPanel`（`/chat` と AI パネルで共通）、本文は `MarkdownMessage` <!-- v2.0 -->
- 画面の操作は `UiControlBridge`（アプリ全体に1つ）。`GET /api/ui/events` を購読し、AI からの遷移とテーマの切替を行う。ブラウザが WebMCP（`navigator.modelContext`）を持つときは、同じ遷移をページの道具としても登録する <!-- v2.0 -->
- 類似事例は `SimilarReportsCard` <!-- v3.0 -->
- 完成形の追加：`PhotoGallery`（写真）、`CapaSection`（詳細の CAPA）、`TriagePanel`・`TriageSuggest`（トリアージ）、`FeedbackButtons`（👍/👎）、`MicButton`（音声入力）、`OntologyGraph`（Ontology のグラフ） <!-- v5.0 -->
- 押せるものには読み上げ用の名前（`aria-label`）を付ける（例：「メニューを開く」「AIアシスタントを開閉」「カラーモード切替」）。画面の試験（Playwright）は役割と名前で部品を探す <!-- v5.0 -->
