# 14 判断モデルによる強化(検索の並べ替え・質問の振り分け・引用の確かめ・読み取りの確かめ)

2026-10-18 追加。LLM は文章を作り、**判断モデル**(decision model。型の決まった判断と確率を返す)は狭い判断だけを受け持つ。
OpenRouter の Decisions API(`POST https://openrouter.ai/api/alpha/decisions`)は、Jev(TypeSafe)のほかに
Perplexity・Liquid・Microsoft・OpenAI などの判断モデルを同じ形で呼べる(2026-10-18 時点で27モデル)。
例アプリでは、その中から機能ごとに測って選んだモデルを使う。実装は `app/backend/services/decisions.py`、
測定は `eval/decisions_1018/`(結果は `report.md`)。報告書トリアージ(`docs/11`)とは別の機能。

## 1. 4つの機能

| 機能 | どこで | 判断モデルに聞くこと | 使い方 |
|---|---|---|---|
| ① 検索の並べ替え | `rag.search`(スマート検索・チャットの事前検索・MCP の search_defect_reports) | 候補30件それぞれが「質問に当てはまるか」(Noul)。候補をまとめて1リクエスト | 確率の高い順に上位を返す。各件に `relevance`、`search_mode` は `hybrid+rerank` |
| ② 質問の振り分け | チャット(`/api/chat/stream`・`/api/chat`) | 質問の種類(Choice:1件・条件で絞る・件数・似た事例を探す・画面の操作・その他) | 確率0.6以上のときだけ、道具の使い方の注意をプロンプトに足す。SSE `route` |
| ③ 引用の確かめ | チャットの回答のあと | 回答の文ごとに、引用した報告書がその文を支えるか(Noul) | SSE `citations`、Langfuse のスコア `citation_support`。無い番号・崩れた番号(例 `KZ2判-0039`)は形で見つける |
| ④ 読み取りの確かめ | 帳票の取込(`/api/ingest/upload`、PDF・画像) | 読み取った値が画像の欄と合うか(Noul を1リクエストに)。合わない欄の位置(Box、Jev 1.14 だけ) | `field_checks`・`verification`・警告。**確信度はこの結果で決める**(合わない項目 0→high、1〜2→medium、3以上→low) |

判断モデルが使えない・失敗したときは、どの機能も今までの動き(ハイブリッド検索の順・注意なし・確かめなし・確信度 medium)に戻る。

## 2. 選んだモデルと理由(`DECISION_PROFILE`)

| 機能 | モデル | 測定(eval/decisions_1018) |
|---|---|---|
| ① 並べ替え | typesafe/jev-1.14(まとめて1リクエスト) | 16問の上位5件の正解 0.56→0.72、1問 約0.4秒。候補ごとに呼ぶ pplx-decider-v1.2 は 0.73 だが 1.1〜2.3秒 |
| ② 振り分け | perplexity/pplx-decider-v1.2 | 117問 98.3%、1回 約0.5秒。LLM:gemini-2.5-flash 99.1%(0.8秒)、claude-sonnet-4.5 97.4%(1.9秒、費用は約200倍) |
| ③ 引用 | liquid/d1-ultra | 54組 100%、約0.5秒。LLM:gemini-2.5-flash 94.4%、claude-sonnet-4.5 90.7%、gpt-4o-mini 81.5% |
| ④ 読み取り | typesafe/jev-1.14 | 読み違い35項目のうち23を検出、正しい223項目の誤検出0、1枚 約0.5秒。LLM:gemini-2.5-flash 26/35・誤検出9(1.6秒) |

アプリの中の時間:検索 API は判断モデルなし 22ms → あり 428ms(中央値)。チャットは振り分けを検索と同時に走らせるので、
足されるのは約0.1秒と、回答のあとの引用の確かめ(約0.5秒)。

## 3. 設定(環境変数)

| 変数 | 既定 | 意味 |
|---|---|---|
| `DECISIONS_ENABLED` | 0 | 1 で4つの機能を有効にする(判断モデルの鍵 `OPENROUTER_API_KEY` か `TYPESAFE_API_KEY` が要る) |
| `DECISION_RERANK` / `DECISION_ROUTE` / `DECISION_CITE` / `DECISION_OCR_VERIFY` | 1 | 0 でその機能だけ止める |
| `DECISION_MODEL_RERANK` などの `DECISION_MODEL_<機能>` | 表のモデル | モデルを替える(替えたら測り直す。確率の出方はモデルで違う) |
| `DECISION_RERANK_MODE` | joint | `per_candidate` で候補ごとに1リクエスト |
| `DECISION_ZDR` | 1 | OpenRouter にデータを残さない経路(ZDR)だけを使う |
| `DECISION_CACHE_TTL` | 600 | 同じ入力の答えを使い回す秒数 |

※ 判断に使う文(質問・報告書の項目・帳票の画像)は OpenRouter と各社に送られる。社外に出せないデータでは使わないか、手元で動く判断モデル(例:Perplexity の pplx-decider は Apache-2.0 で公開)を検討する。

## 4. 画像について

- 画像は長い辺を1568画素以下に縮めて送る(Jev は縦・横とも280〜1568画素)。PDF は1ページ目を画像にする(pypdfium2)。
- 画像の入力と Box は TypeSafe が「試作向け」とする機能。形や答えが版で変わることがある。Box の枠は欄全体を囲むことが多い(18欄中14欄で文字の位置を含む)。
- 読みにくい画像では、照らし合わせる側も見えにくい。確信度 low のときは必ず原本を見る。

## 5. 限界

- 判断モデルが足すのは「道具の使い方の注意」と「確かめの結果」まで。最後に文を書くのは LLM なので、正しさの保証ではない(画面の試しで、gemma4:26b が6件を並べながら「5件」と書いた例がある)。
- 並べ替えは候補の中でしか直せない。候補30件に正解が入っていない問い(言い換え)には、別名の辞書や質問の言い換えが要る。
- 測定の問題は小さい(117問・16問・54組・12回)。自社のデータでは、固定の問題で測ってから採る。
