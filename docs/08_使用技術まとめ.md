# DefectReport AI — 使用技術まとめ

本アプリ(2026年度AIセミナー 完成イメージアプリ)で使われている技術を、**層ごとに「何をしているか / なぜこれを選んだか / セミナーのどの回で学ぶか」** の観点で整理したものです。

```
利用者 → [frontend: React+TS/nginx] → [backend: FastAPI] → PostgreSQL / SQLite
                                          │  ├→ Chroma(ベクトル検索)
                                          │  └→ /mcp/ (FastMCP・9ツール)
                                          └→ [opencode: opencode serve] → OpenRouter(LLM)
              ※ 4サービスを Docker Compose で一括起動
```

---

## 1. フロントエンド

| 技術 | バージョン | 役割 |
|---|---|---|
| **React** | 19 | 画面のコンポーネント構築。宣言的UIの土台 |
| **TypeScript** | 6 | 型付きJS。APIレスポンスの型を定義し、バグをコンパイル時に検出 |
| **Vite** | 8 | 開発サーバー(HMR)とビルド。dev時は proxy で backend へ中継 |
| **MUI (Material UI)** | 9 | UIコンポーネント集。テーマは「CNCコックピット」(ライト/ダーク両対応、`theme.ts` が正) |
| **Recharts** | 3 | KPIダッシュボードのグラフ(パレート図・p管理図・トレンド等) |
| **React Router** | 7 | 画面遷移(一覧/詳細/チャット/分析/ダッシュボード/マスタ) |
| **axios** | 1 | REST API 呼び出し。SSE のストリーミング受信は fetch を併用 |
| **oxlint** | 1 | 高速リンター |
| **nginx** | - | Docker 時の静的配信と `/api` リバースプロキシ |

**学ぶ回**: 第2回(設計・雛形)、第5回(ダッシュボード)、第6回(仕上げ)

## 2. バックエンド

|---|---|
| **FastAPI** (Python 3.12) | REST API 本体。自動で OpenAPI ドキュメント(/docs)生成 |
| **uvicorn** | ASGI サーバー(非同期処理・SSE 対応) |
| **SQLAlchemy** | ORM。SQLite/PostgreSQL を同一コードで扱う抽象化層 |

| **pandas / openpyxl** | 帳票 Excel の読み込み・模擬データ生成 |
| **reportlab** | OCR デモ用の帳票 PDF 生成 |
| **httpx** | OpenCode サーバーへの HTTP クライアント(ストリーミング対応) |
| **pytest** | テスト 28 件(API 正常系/異常系・集計ロジック) |

**学ぶ回**: 第2回(雛形・データモデル)、第3回(API組み込み)、第6回(テスト)

## 3. AI・エージェント層(このアプリの心臓部)

| 技術 | 役割 |
|---|---|
| **OpenCode** (`opencode serve` :4096) | エージェント実行エンジン。チャット・帳票抽出・4M分析すべての生成を担当。ツール(MCP)を自律的に呼び出す |
| **OpenRouter** | LLM ゲートウェイ。1つのAPIキーで複数モデルを切替(既定 `anthropic/claude-sonnet-4.5`、代替に `openai/gpt-4o-mini`・`google/gemini-2.5-flash`) |
| **MCP (FastMCP)** | backend が `/mcp/` で報告書データを **9ツール**(読取7+書込2)として公開。OpenCode がチャット中に自律呼び出し。書き込みは明示依頼時のみ |
| **Anthropic API** (`anthropic` SDK) | 任意の代替経路。`ANTHROPIC_API_KEY` があれば帳票抽出・4M分析を直叩き(チャットは OpenCode 専用) |
| **構造化出力(JSON抽出)** | 帳票の自由文・画像から項目を JSON スキーマで抽出(vision 含む) |
| **SSE (Server-Sent Events)** | 応答のストリーミング配信。OpenCode のイベント(`message.part.delta`)を中継し逐次表示 |

**設計上のポイント**
- モデルは `{"providerID","modelID"}` のネスト形式で指定。ファイル添付は FilePartInput(data URL)
- MCP ツールを変更したら `docker compose restart opencode` が必要(ツール一覧は起動時取得)
- チャット履歴は `chat_sessions` / `chat_messages` に永続化(sources・tools・thinking 込み)

**学ぶ回**: 第3回(API・構造化出力・SSE)、第4回(RAG・Tool use・MCP)

## 4. RAG(検索拡張生成)

| 技術 | 役割 |
|---|---|
| **Chroma** | ベクトルDB(ファイル永続化)。報告書の意味検索の索引 |
| **sentence-transformers** `intfloat/multilingual-e5-small` | 日本語対応の埋め込みモデル(ローカル実行)。未導入時は**キーワード検索に自動フォールバック** |
| **根拠付き回答** | 検索ヒットした報告書を `[KZ25-XXXX]` 形式で引用し、出典を UI に表示 |

**学ぶ回**: 第4回

## 5. データストア

| 技術 | 役割 |
|---|---|
| **PostgreSQL 16** (Docker時) / **SQLite** (ローカル時) | 報告書・マスタ・チャット履歴の正本。同一スキーマの二段構え |
| **psycopg** | PostgreSQL ドライバ |
| **模擬データ** | `data/generate_mock_data.py`(seed=42)で不良報告100件+帳票 Excel 全件+PDF 10件を生成 |

**学ぶ回**: 第2回(ER設計・正規化)

## 6. 実行基盤・開発プロセス

| 技術 | 役割 |
|---|---|
| **Docker Compose** | db / backend / opencode / frontend の4サービス一括起動。ローカルは venv+npm+SQLite でも可 |
| **環境変数 (.env)** | `OPENROUTER_API_KEY` 等の秘密情報管理(コード直書き禁止) |
| **Claude Code** | 本アプリ自体を「バイブコーディング」で構築。要件定義→仕様書(docs/01〜07)→実装→テスト→ドキュメントの全工程 |
| **mingrammer/diagrams** | `docs/diagrams/generate_diagrams.py` で構成図を再生成 |

**注意**: ポート5173は別プロジェクトが常用のため、検証は `FRONTEND_PORT=5373 docker compose up -d`
